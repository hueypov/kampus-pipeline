# Pipeline CLI capability matrix

This file records which lifecycle and repository safeguards are supplied by the portable core. A listed adapter is intentionally unavailable until the adopting repository supplies its own inputs and activation policy.

| Capability | Status | Boundary |
|---|---|---|
| `main-sync` | Core | Resolves the primary branch from `git.primaryBranch` or `origin/HEAD`; dry-run by default; never resets or force-checks out. |
| `trivial-diff classify` / `route` | Core | Fail-closed classifier and the single lightweight-review route authority. `route` selects `review-trivial` only when immutable policy explicitly enables it, every shared classifier proves a single ordinary surface, and the caller asserts SHA-bound reduced-gate support; every other result is `full-review`. |
| `gh-compat lint-skills` | Core | Strict YAML-frontmatter validation plus an optional, repository-configured GitHub CLI compatibility lint. The optional PATH shim is disabled unless `github.cliCompatibility.pathShim.enabled` is explicitly configured. |
| `worktree-sweep` | Core | Inspects only configured managed roots and review prefixes; dry-run by default; never uses force removal. |
| `class-probe classify` | Core | The shared, fail-closed changed-path classifier for reviewer dispatch, shipping, and delivery CI. Repository-owned `github.review.classification` patterns decide code, docs, skills, and optional design surfaces. |
| `guard-content-probe candidates` / `classify` | Core | A shared, fail-closed classifier for decision records that change a repository safeguard. It is core tooling, while `github.shipping.guardContent` remains an explicit repository-owned convention: disabled with empty path/vocabulary arrays by default. |
| `cp-cardinality decide` | Core pure decision authority | Makes the one deterministic protected-change approval decision from supplied authority members, author, current-revision non-author approval count, and the narrow sole-author exception fact. It performs no provider I/O, policy lookup, or repository mutation. |
| `cp-cardinality evidence-github-team` | Core explicit GitHub-team evidence adapter, policy-controlled | Resolves the configured GitHub-team authority and current-revision facts for `decide`; it is available only when the immutable repository policy enables `github.shipping.protectedChangeApproval` with `authority.provider: "github-team"`. The default is disabled with no organization, team, or marker. |
| `protected-change-policy regex` / `paths` / `classify` | Core | Read-only protected-boundary authority. It derives its complete scope from `github.shipping.controlPlanePaths`; an explicit `--policy-ref` is read immutably. Unreadable policy emits a match-all fallback for shell consumers and routes classification to `protected`. |
| `ref-guard` | Core primary-checkout safety boundary | A generic Git `reference-transaction` hook for a configured/discovered primary ref and shared primary checkout. `pipeline init` installs the managed hook and refuses rather than overwriting a foreign hook. |
| `primary-index-guard` | Core capability; explicit repository-enabled Git pre-commit installation | A pure staged-deletion guard for the proven shared primary checkout. `git.primaryIndexGuard` owns protected prefixes and thresholds; only a deliberate exit 3 blocks, and the installer never overwrites an unrelated hook. |
| `reachability-guard check` | Optional, repository-configured feature adapter | Disabled safely by default. When `optionalAdapters.featureReachability.enabled` is true, repository-owned paths and patterns identify feature declarations, consumer sources, journey registrations, and stated exemptions. It fails closed on zero scope and unknown keys. |
| `catalog-guard` | Optional pnpm catalog/workspace adapter | Disabled unless `.pipeline/optional-workflow-policy.json` explicitly enables `adapters.catalogGuard` and supplies its workspace manifest, package scope, dependency fields, permitted specifier forms, named catalogs, and reasoned exceptions. It only reads manifests. |
| `adoption-lint` | Optional evidence/adoption-governance adapter | Disabled unless `.pipeline/optional-workflow-policy.json` explicitly enables `adapters.adoptionLint` and supplies a corpus, governed concepts, authority/evidence patterns, and linted exemptions. It only reads configured corpus files. |
| `ship-digest` | Core renderer with repository-owned display and release adapters | The command is a pure, lossless projection of gathered merged-work entries. Category/type layout and any release-state adapter belong to `github.shipping.shipDigest`; the CLI never calls a provider or changes release state. |
| `codeowners-cp`, `control-plane-paths`, provider-specific GitHub helpers, `fanout-guard` | Product or infrastructure adapters | Require a provider, product data model, ownership policy, or release authority. `protected-change-policy` is the portable replacement for the former source-specific protected-path emitter. |
| `design-token-guard`, `design-inventory` | Optional design-system adapters | Disabled by default. A repository must explicitly configure source globs, formats or JSDoc tags, exceptions, and the generated descriptive artifact. `design-inventory check` is read-only; `generate` writes only the configured descriptive artifact and never a declared normative artifact. |

An adapter must declare its configuration, caller, failure behavior, and test fixture before it may be enabled. Do not add a command-shaped stub that silently passes without those repository-owned inputs.
