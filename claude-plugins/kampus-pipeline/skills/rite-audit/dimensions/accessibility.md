# Accessibility

Audit the controls used by the documented journey, not every page in the
application. At minimum, check that a keyboard-only user can reach and operate
the critical controls, visible labels identify interactive elements, focus is
not lost after a state change, and automated accessibility tooling—when the
repository supports it—reports no unreviewed critical violations.

Report the affected route/view, control, action, observed behavior, and tool
output. A tool that cannot run is a blocked or inconclusive observation, never
an automatic pass.
